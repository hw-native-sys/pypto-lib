@pl.jit.inline(auto_scope=False)
def paged_attention_pypto_swpipe(...):
    active_batch = pl.tensor.dim(seq_lens, 0)
    num_tasks = active_batch * 8

    with pl.spmd(24, sync_start=True, deps=[...]) as attn_tid:
        core = pl.tile.get_block_idx()

        # ① 准备当前 token：Q/K norm、RoPE、追加 K/V cache（第 4 章）
        for aiv_id in pl.split_aiv(2):
            phase0(...)

        publish_gm_and_sync_mixed_cores()

        for task in pl.range(core, num_tasks, 24):
            # AIC loop
            for tick in pl.range(stack_count + 2):
                if tick < stack_count:
                    # ② QK：计算当前 stack 的 scores（第 5 章）
                    produce_qk(stack=tick)
                if tick >= 2:
                    # ④ PV：计算两轮前 stack 的 P @ V（第 7 章）
                    consume_pv(stack=tick - 2)

            # AIV loop
            for aiv_id in pl.split_aiv(2):
                for tick in pl.range(stack_count + 2):
                    if tick < stack_count:
                        # ③ Softmax：更新 m/l 并写出 P（第 6 章）
                        online_softmax(stack=tick)
                    if tick >= 2:
                        # ④ 输出更新：rescale O 并累加 P @ V（第 8–9 章）
                        update_output(stack=tick - 2)

    return attn_tid
Tips:

AIC loop 和 AIV loop 在 AIC 和 AIV 上并行执行；第 8 节的三个 READY events 决定谁等待、谁继续。

从公式确定计算粒度

先决定一个 task 算什么，再写任何 load 或 matmul。

1.1 数学目标

ScoresQ @ Kᵀ / √128
ProbabilityP = softmax(scores)
Contextcontext = P @ V

1.2 模型维度决定 Tile

已知维度Kernel 决定
40 个 Q heads，8 个 KV heads1 个 KV head 服务 5 个连续 Q heads
head dim = 128QK/PV 的 cube K 维固定为 128
page size = 128 tokens每次加载一个 [128,128] K/V page

Paged KV 在 GM 中不连续。访问第 logical_page 前，必须先查表得到物理页：

1.3 一个 task 算什么

一个 task = 一个 batch row + 一个 KV head + 对应的 5 个 Q heads

它遍历该请求的全部历史 K/V pages，最后写出 5 行 context。

连续编号 → 任务坐标 batch = task // 8

每 8 个 tasks 切换到下一个 batch。

选择 KV/Q heads kv_head = task % 8

q_head_begin = kv_head * 5。

task 9 · complete mappingbatch = 2 example
task 9
→ batch        = 9 // 8 = 1
→ kv_head      = 9 %  8 = 1
→ q_head_begin = 1 *  5 = 5
→ 负责 batch 1、KV head 1、Q heads 5–9

1.4 Task、Page、Stack 是三种粒度

Q physical [16,128] Q valid [5,128] K/V page [128,8,128] stack ≤ 512 tokens
拆错 task 的结果

按单个 Q head 拆会把相同 K/V pages 重复加载 5 次；按整个 batch 拆又会减少并行度并扩大单 task 工作集。

定义 Entry、Helper 和 Scratch

Entry 声明读写方向并分配 GM 中间区；inline helper 负责真正的 mixed-core 计算。

2.1 Entry 只在边界声明方向

entry signaturedirection lives here

@pl.jit.inline helper 使用裸 pl.Tensor。它收到的 TaskIds 只进入 deps；独立 entry 用 task_dummy 占位。

2.2 五个中间 Tensor

three-slot row layoutGM mailbox

每个 core 独占三个 slots。每槽为 cube 预留 16 行，但一个 task 只有前 5 行有效；消费后，后续 stack 会复用该槽。

4

写 Phase 0 和 GM Barrier

先把当前 decode token 的 Q/K/V 准备好，再让 Attention 主体读取它们。

什么是 mixed barrier？

它是 AIC 和 AIV 共同参与的同步点：负责 Phase 0 的 AIV 发布完 Q/K/V 的 GM 写入后，所有 core 才继续执行 Attention 主体。

4.1 把 Phase 0 工作分给 AIV

phase-0 assignment32 physical AIV lanes
for aiv_id in pl.split_aiv(2, mode=pl.SplitMode.NONE):
    rope_core = core * 2 + aiv_id
    if rope_core < 32:
        for it in pl.pipeline(4, stage=2):
            g_idx = rope_core + it * 32
            if g_idx < 8 * active_batch:
                kv_head  = g_idx // active_batch
                batch_idx = g_idx % active_batch

g_idx 覆盖 8 × active_batch 个 (kv_head, batch) 组合。每个组合准备 1 个 K head、1 个 V head 和共享它们的 5 个 Q heads。

4.2 同时写 Q、K、V

路径计算写到哪里
Kk_proj × inv_rms → K head norm → RoPEBF16，追加到 K cache 当前 slot
Vv_proj × inv_rmsBF16，追加到 V cache 当前 slot
Q5 heads → Q head norm → RoPEBF16，写入 q_tnd_flat 的 5 行
Q compute [16,128] · valid 5 rows K compute [8,128] · valid 1 row norm accumulation FP32 Q/K/V store BF16 GM

Q reduction pad 到 16 行，K reduction pad 到 8 行；padding 行为 0，不影响有效行的 norm。

4.3 Cache 地址先 clamp，再加 layer base

cache append addressavoid crossing layers
write_slot = pl.max(
    pl.cast(slot_mapping[batch_idx], pl.INDEX),
    0,
)
cache_row = layer_cache_base_token_rows + write_slot

Serving 的单页 profile warmup 会传入 -1。必须先把 slot clamp 到 0，再加 layer base；反过来会让第 N 层写到第 N−1 层的最后一行。

4.4 发布 GM 写入

publish → arrive → refetchAIC + AIV
pl.system.cacheinvalid()
pl.system.fence()
pl.system.syncall(core_type="mix")
pl.system.cacheinvalid()
  1. fence 把 Phase 0 的 Q/K/V GM writes 发布出去。
  2. syncall 等所有 mixed cores 到达同一个同步点。
  3. barrier 后再次 invalidate，确保后续 MTE2 load 不读取旧 cache line。
只有 syncall 不够

syncall 负责“都到了”，不负责自动发布写入或清掉读取端的旧 cache。

6

写 AIV Online Softmax

AIV 不一次保存整条序列的 scores，而是每次吸收一个最多 512-token 的 stack。

6.1 两个 lanes 分掉 5 行

AIV laneRow offset有效行物理 Tile
00Q heads 0–1，共 2 行[8,512]
12Q heads 2–4，共 3 行[8,512]

6.2 等 scores，再 mask 尾部

score load + tail maskAIV Vec
pl.system.sync_wait(QK_READY_EVENT, core_type="aiv", ...)
scores = pl.load(score_transfer, [slot_row + lane_row, 0], ...)
scores = pl.tile.muls(scores, 1.0 / math.sqrt(128))

valid_cols = pl.min(512, seq_len - stack * 512)
scores = pl.set_validshape(scores, lane_rows, valid_cols)
scores = pl.fillpad(scores, pad_value=pl.PadValue.min)

最后一个 stack 不足 512 tokens 时，无效列必须在 row_max 和 exp 前填成负无穷，使其概率严格为 0。

6.3 用运行状态合并多个 stacks

普通 softmax 需要整行的最大值和指数和。Online softmax 把它们改成跨 stack 更新的状态：

online-softmax recurrencei = current stack
mᵢ = max(mᵢ₋₁, row_max(Sᵢ))
rᵢ = exp(mᵢ₋₁ - mᵢ)
Pᵢ = exp(Sᵢ - mᵢ)
lᵢ = rᵢ * lᵢ₋₁ + row_sum(Pᵢ)
mᵢ到目前为止的最大值

让 exponent 保持稳定。

rᵢ旧状态的缩放因子

最大值变大时，先缩放旧累计量。

lᵢ到目前为止的指数和

所有 stacks 结束后用于最终归一化。

m/l/r 保持 FP32。Pᵢ 按 rint 转成 BF16 写入 probability_transfer，然后 set SOFTMAX_READY_EVENT。

Pᵢ 还不是最终 softmax

它尚未除以最终的 l。如果在每个 stack 内单独归一化，再把结果相加，跨 stack 的概率比例会错误。

8

把三个阶段接成流水

QK、softmax、PV/output 不等一个 stack 全部结束才开始下一个，而是让多个 stacks 同时处于不同阶段。

8.1 两轮预启动的流水设计

流水把 QK + softmax 作为生产端，把 PV + output update 作为消费端。生产端处理 stack i 后，消费端固定晚两轮处理同一个 stack，使多个 stacks 能同时处于不同阶段。

two-tick prelaunchlogical pipeline
for tick in pl.range(stack_count + 2):
    if tick < stack_count:
        produce(stack=tick)      # QK + softmax
    if tick >= 2:
        consume(stack=tick - 2)  # PV + output update

前两轮只启动 S0、S1；之后每轮同时启动当前 stack、回收两轮前的 stack。 所有 stacks 启动后，再用最后两轮 drain 尚未回收的 PV，所以循环长度是 stack_count + 2。

8.2 三槽 Ring、Events 和 Rescale 对齐

到 tick=2 时，S0、S1、S2 同时处于流水中，所以三个 transfer tensors 都需要三个互不覆盖的 slots：slot = stack % 3。

8.3 三个 READY Events

EventSetWait保护的数据
QK_READY_EVENTAICAIVFP32 scores
SOFTMAX_READY_EVENTAIVAICBF16 P
PV_READY_EVENTAICAIVFP32 P@V

8.4 Rescale 也要延迟两轮

rᵢ 在 softmax 处理 Sᵢ 时产生，但对应的 PVᵢ 要到两轮后才返回。两个 pending slots 让它们重新对齐：

two-entry rescale FIFOAIV Vec FP32
(pending0, pending1)
(1, 1) → (1, r0) → (r0, r1) → (r1, r2) → ...

O = pending0 * O + PVᵢ

例如 tick=2 回收 S0 时，pending0=r0；tick=3 回收 S1 时，pending0=r1。

Ring 槽与 Rescale FIFO 解决的是两件事

Ring 防止 GM 中间结果互相覆盖；FIFO 保证两轮前的 PV 使用同一个 stack 产生的 rescale。

9

补齐 Tail、动态形状和最终输出

完整 stack 有四页；最后一个 stack 可能只有 1、2 或 3 页，不能访问不存在的 block-table 项。

9.1 固定四种 PV 分支

真实 pagesV slotsP slotsCube 计算
100matmul
20, 10, 1matmul + matmul_acc
30, 1, 20, 1, 0matmul + 2×matmul_acc
40, 1, 2, 30, 1, 0, 1matmul + 3×matmul_acc

QK 和 PV 都只加载真实 pages；AIV 再用 valid_cols mask 最后一页中无效的 tokens。缺失页不发 block-table/K/V/P load，也不做对应 matmul。

9.2 动态请求仍使用同一份 Kernel

  • batch 来自 seq_lens 的 tensor descriptor。
  • 每个请求独立读取 seq_len，计算自己的 page/stack count。
  • physical pages 可以乱序、非连续，也可以共享 prefix。
  • layer_cache_base_token_rows 选择 packed multi-layer cache 中的当前层。

9.3 归一化并写回 5 行 context

    context,

lane 0 写 2 行，lane 1 写 3 行。返回的 attn_tid 让调用者约束后续 output projection 或下一次 scratch reuse。

Tail 有两层边界

先避免访问缺失的 pages，再 mask 最后一页里的无效 tokens；只做其中一个仍会越界或把 padding 算进 softmax。
